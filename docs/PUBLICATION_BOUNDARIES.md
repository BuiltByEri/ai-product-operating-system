# Publication Boundaries

AAPOS public release content must be safe for open publication.

## Allowed

- Vendor-neutral AAPOS methodology.
- Public, fictional examples clearly labeled as fictional.
- General product, engineering, risk, and governance concepts.
- Reference skill contracts that preserve human accountability.
- Validation scripts that reduce publication risk.

## Not Allowed

- Client-owned work or client-specific artifacts.
- Internal stakeholder names.
- Internal project names.
- Non-public repository links.
- Local machine paths.
- Secrets, tokens, credentials, or keys.
- Confidential screenshots, datasets, or attachments.
- Assessment-specific phrasing unrelated to the public framework.
- Unsupported claims of production deployment, adoption, customer results, revenue impact, or measured outcomes.

## Review Standard

Before publication, run the validation scripts and manually review all files. The safety scan reduces risk, but it cannot guarantee that all sensitive or proprietary material has been removed.

## Fictional Example Standard

Fictional examples must be labeled as fictional, use invented names, avoid measured production outcomes, and avoid implying real deployment.
